Run your pipeline’s checks before you push

Your change passes its tests on your laptop, then the pull request turns red in Tekton because of a spelling check or a naming rule you never ran. tkn-innerloop reads the pipeline in your repository and runs those same checks on your machine, in the same container images, in a few seconds.

uv tool install git+ssh://git@github.com/openshift-pipelines/tkn-innerloop

How it works, step by step

A real session in the Pipelines-as-Code repository. Every screen below is the actual output, trimmed where noted.

  1. You change some code

    Someone adds a small Go test. It has two problems a reviewer would catch: a typo in a comment, and an underscore in the test name, which the project’s rules forbid.

    pac> cat pkg/params/innerloop_demo_test.go
package params

import "testing"

func TestInnerLoop_ConfigValidation(t *testing.T) {
	// Verify teh default configuration.
	got := "pac"
	if got != "pac" {
		t.Errorf("unexpected value: %s", got)
	}
}

  2. Your usual tests pass

    The code works, so go test is happy. The pipeline also checks spelling and test names, and those checks only run in Tekton after you push. Normally you would find out from a red pull request and push again.

    pac> go test -run TestInnerLoop ./pkg/params
ok  	github.com/openshift-pipelines/pipelines-as-code/pkg/params

  3. An agent writes a local plan, once

    tkn-innerloop gives the pipeline file to a coding agent. The agent reads the scripts and the files they use, then decides for each step whether it can run on a laptop and what has to change for that. It took five seconds here.

    The plan is saved in your cache folder, never in your repository.

    pac> tkn-innerloop generate .tekton/linter.yaml \
       --steps codespell,check-test-conventions -o /tmp/linters.json

  4. You read the plan

    Nothing runs on a guess. The plan gives every step a decision and a reason, and shows each change made to a script.

    Here the pipeline used details only GitHub knows, such as the commit your pull request starts from. The plan swaps them for the same details taken from your local git checkout.

    pac> tkn-innerloop validate /tmp/linters.json --diff

  ✓ RUN LOCAL  linters/check-test-conventions

                 tree plus untracked files.

  ↷ SKIP       linters/shellcheck

+base_sha="$BASE_SHA"

  5. The checks run on your machine

    Each step runs in a container built from the image the pipeline names, with your working copy mounted inside. Changes you have not committed yet are checked too.

    Both mistakes show up, with the same messages CI would have printed.

    pac> tkn-innerloop run /tmp/linters.json --steps codespell

  6. Fix it and run again

    After the fix, the same plan runs again and both checks pass. From now on the saved plan is reused without asking the agent. A new plan is made only when the pipeline, or a script it reads, changes.

    Then you push, and the cluster runs the full pipeline as usual.

What it leaves alone

Anything that reaches outside your machine

Cloning the repository (you already have it), pushing images, deploying, and posting to GitHub stay on the cluster. So do steps marked to skip local runs, and any pattern you list in .tekton-innerloop.yaml.

Steps it cannot run safely

When the agent cannot work out how to run a step, it marks it unresolved. The run then says the result is incomplete instead of reporting a quiet pass.

Your repository

Plans, downloaded Tekton bundles and build caches live in ~/.cache/tkn-innerloop. Nothing is added to your checkout, so linters and git status never see it.

Your judgement

The agent edits scripts, and those scripts run on your machine. Read a new plan with validate --diff before you trust it. Your CI still runs the whole pipeline.

It understands plain Tekton PipelineRuns and Pipelines, Pipelines-as-Code templates, Konflux pipelines, Tekton bundles and tekton-caches.

Try it

You need Python 3.11 or newer, uv, Podman or Docker, and the pi coding agent signed in to a model provider.

# install the command
uv tool install git+ssh://git@github.com/openshift-pipelines/tkn-innerloop

# or try it once without installing
uvx --from git+ssh://git@github.com/openshift-pipelines/tkn-innerloop tkn-innerloop --help

# then, inside a repository with a .tekton/ folder
tkn-innerloop run

# optional: teach your coding agent to use it
tkn-innerloop skills install

Run uv tool upgrade tkn-innerloop later to pick up new versions. The README covers every option.
